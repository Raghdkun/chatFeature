# Chat data layer (P4 spine)

> Status: implemented foundation for the four P4 tracks (4A domain + REST, 4B realtime, 4C dashboard, 4D embed panel). Shapes of the realtime payloads and REST resources stay defined by
> [realtime-events.md](realtime-events.md) and [rest-shapes.md](rest-shapes.md); this file says **what exists in code**, under which names, and the rules the tracks write against.
> The tracks use these names as they are; a change goes through the orchestrator.

## Tables (`database/migrations/2026_11_10_*`)

Statuses, types and responses are plain `string` columns backed by PHP enums (adding a case needs no `ALTER`). Public ids are `ulid`s; integer keys never leave the server. Timestamps are stored with second precision (the API prints `.000`; ordering is by `seq`, never by time).

| Table (model) | Notes |
|---|---|
| `visitors` (`Visitor`) | `external_id` = the identity token's `sub` (<= 255), `verified`, `name` 120, `email` 190, `phone` 40, `meta` json, `first_seen_at`, `last_seen_at`. **Unique `(widget_id, external_id)`**: NULLs are distinct on MySQL and SQLite, so any number of anonymous visitors coexist. FK `widget_id` cascades. |
| `visitor_sessions` (`VisitorSession`) | `token_hash` char(64) unique (sha256 of the plaintext `vt_...`), `expires_at`, `revoked_at`, `last_used_at`, `page_url`/`referrer` 2048, `page_title` 255, `user_agent` 255, `locale` 12. FKs `visitor_id`, `widget_id` cascade. |
| `conversations` (`Conversation`) | Exactly the columns of the brief. `ticket_no` varchar(12) unique, generated by the model (`TicketNumberGenerator`: 6 characters from `ABCDEFGHJKMNPQRSTUVWXYZ23456789`, widened to 8 on repeated collisions). FKs: `widget_id`, `visitor_id` cascade; `visitor_session_id`, `category_id`, `assigned_agent_id` **null on delete**. |
| `conversation_events` (`ConversationEvent`) | Append-only audit trail (`type` 40, `actor_type`, `actor_id`, `payload` json, `created_at`); index `(conversation_id, id)`; cascades with the conversation. |
| `conversation_agent_alerts` (`ConversationOffer`) | The offers. **Unique `(conversation_id, user_id)`**: one row per agent and conversation, so a re-queue (transfer) must reset or replace the agent's row instead of inserting a second one. Index `(user_id, responded_at)`. No `created_at` / `updated_at`: the row carries `offered_at`, `expires_at`, `responded_at`. |
| `messages` (`Message`) | `seq` unsigned, unique `(conversation_id, seq)` and `(conversation_id, client_msg_id)` (NULL never collides), `sender_user_id` null on delete, `created_at` only. `FULLTEXT(body)` on MySQL / MariaDB only. |
| `attachments` (`Attachment`) | `message_id` null on delete (an upload exists before the message that references it), `uploader_type` visitor/agent, `path`/`thumb_path` 512, `sha256`, `original_name` 120 (staff-only), `created_at` only. |
| `ratings` (`Rating`) | `conversation_id` unique, `score` tinyint (1-5 is enforced by the request), `comment` text. |
| `agent_presence` (`AgentPresence`) | One row per user (`user_id` unique, cascades), `status` default `offline`, `is_manual`, `last_seen_at`, `last_heartbeat_at`. P5 adds the Redis ZSET behind this model. |

Indexes serve: staff queue `(status, queued_at)`; agent list `(assigned_agent_id, status, last_message_at)`; offline tickets `(type, status, created_at)`; admin history `(widget_id | category_id | status, created_at)`; `updated_after` refetches `(updated_at)`;
one-open-conversation lookups `(visitor_id, type, status)` and `(visitor_session_id, status)`; sweeps `(status, queue_expires_at)`, `(status, idle_expires_at)`, `(status, rating_window_expires_at)`.
`workspace_id` (nullable, indexed) exists on `visitors` and `conversations` only; no new unique index spans the workspace, so no `workspace_key` column was needed.

## Enums (`App\Domain\Chat\Enums`, string-backed, `#[TypeScript]` -> `App.Domain.Chat.Enums.*`)

`ConversationStatus` (queued, active, ended, closed, missed) · `ConversationType` (live, offline) · `ConversationEndedBy` (visitor, agent, admin, system) · `ConversationCloseReason` (rated, skipped, idle, timeout, system, cancelled) ·
`MessageType` (text, image, system) · `SenderType` (visitor, agent, system) · `OfferResponse` (accepted, taken, expired, dismissed) · `PresenceStatus` (online, away, offline; `isAvailable()`) ·
`ActorType` (visitor, agent, admin, system: `conversation_events.actor_type`) · `SessionRevokeReason` (role_removed, deactivated, auth_revoked).

### State machine

`ConversationStatus::allowedTransitions()` / `canTransitionTo()` (a status never transitions to itself):

| From | To |
|---|---|
| `queued` | `active` (atomic claim), `missed` (queue timeout), `closed` (visitor cancels / admin dismisses) |
| `active` | `ended` (either side ends), `closed` (idle sweep, or an offline ticket resolved), `queued` (transfer, agent deactivated) |
| `ended` | `closed` (rated, skipped, rating window elapsed) |
| `missed`, `closed` | none (terminal) |

`isOpen()` = queued or active (`ConversationStatus::open()` / `openValues()`); `isTerminal()` = missed or closed. `ended` is **not** open: the visitor is only rating.
`Conversation::canTransitionTo()` adds the type rule: an **offline** ticket is never `ended` or `missed` (it is queued -> active -> closed).
**Offline tickets are separate rows.** `missed` stays terminal; the offline form (after `missed`, or directly after `409 no_agents`) creates a **new** `type = offline`, `status = queued` conversation (`queue_expires_at` null). Record the link in the new row's `created` event payload (`{origin: <missed ulid>}`).
Writers use guarded `UPDATE ... WHERE status = :from [AND ...]` statements; the table says what is legal, the SQL makes it race-free.

## Models, scopes, policy

- `Conversation::scopeOpen()`; `scopeVisibleTo(User)`; `isOfferedTo(User)`; relations `widget, visitor, visitorSession, category, assignedAgent, messages (by seq), events, offers, attachments, rating`. `User` gains `assignedConversations(), conversationOffers(), presence(), categories()`; `Widget` `visitors(), conversations()`; `Category` `conversations()`.
  Dates are `CarbonImmutable` in this app. Models are written by actions only (all columns are `#[Fillable]`); never pass raw request input to them.
- `ConversationOffer::scopeOpen()` / `isOpen()`: **open = `responded_at IS NULL AND expires_at > now`**.
- **`visibleTo`** (and its PHP twin `ConversationPolicy::viewAsStaff()`, kept in step by a parity test): inactive users and users with neither role: nothing. Active admin: everything. Active agent: conversations assigned to them, **or** `status = queued` and (an open offer to them, **or** an offline ticket whose category they serve).
  The offline-ticket branch is an addition to the original text (agents would otherwise never see the offline-ticket queue, `chat-ui-p4.md`); it grants no live-chat visibility.
- `ConversationPolicy` (registered in `ChatServiceProvider`): `viewAny`, `view`/`viewAsStaff` (the rule above; **the 4B channel authoriser calls `viewAsStaff`**), `claim` (active **agent** (`is_agent`) who can see a queued, unassigned conversation), `send` (active chat; assigned agent or admin), `end` (active **live** chat; assigned agent or admin), `transfer` (active chat; assigned agent or admin),
  `assign` (admin; queued/active), `close` (not terminal; queued: admin only, otherwise assigned agent or admin), `viewRating` (admin only). Category eligibility, presence and `max_concurrent_chats` belong to 4A's claim action.
  **`Gate::before` (AuthModeServiceProvider) returns true for every ability of an active admin**, so `$admin->can('send', $closedConversation)` is true: state-sensitive actions must rely on their guarded SQL (or call the policy methods directly), not on `can()` alone.
- `VisitorSession::owns(Conversation)`: the session created it and the visitor matches. Cross-visitor access is `404`, never `403`.
- Category guard: `ConversationCategoryUsageChecker` (bound in `ChatServiceProvider`) replaces the P3 stub: `409 category_in_use` while a queued or active conversation (live or offline) belongs to the category. The `Null` checker was removed.

## Visitor tokens (`App\Domain\Visitors`)

`VisitorTokenService`: `issue(Visitor, array $context = [], ?CarbonInterface $expiresAt = null): IssuedVisitorToken` (`plaintext`, `session`; TTL from `chat.visitor_session_ttl_days`; context keys `page_url, page_title, referrer, user_agent, locale`, bounded),
`find(string): ?VisitorSession` (any state; null for anything that is not a well-formed `vt_` + 40 `[A-Za-z0-9]` token; lookup by sha256 then `hash_equals`), `resolve(string)` (active only), `touch(session)` (at most once per 60 s; also `visitors.last_seen_at`), `revoke(session)` (idempotent), `revokeAllFor(Visitor)`; static `generate()`, `hash()`, `looksLikeToken()`.
Middleware alias **`visitor`** (`AuthenticateVisitor`, use after the `widget` group): `Authorization: Bearer vt_...` only (not query string, not cookies). Unknown / malformed -> `401 unauthenticated`; revoked or expired -> `401 session_revoked`. Success sets request attributes `visitor_session` (`VisitorSession`) and `visitor` (`Visitor`); `$request->user()` stays null.
It does not check that the widget is still enabled: 4A decides what a disabled or deleted widget means for an open session.

## Rules for the tracks

1. **Guarded writes.** Change `status` only with `UPDATE ... WHERE id = :id AND status = :from` (and `assigned_agent_id IS NULL` for the claim); check `Conversation::canTransitionTo()` first. Write the `conversation_events` row in the same transaction, dispatch events after it (they wait for the commit anyway).
2. **`seq`** is allocated inside the transaction that inserts the message (for example `UPDATE conversations SET last_seq = last_seq + 1 ...` then read it back with a lock); `Message::factory()` keeps `last_seq` in step in tests.
3. **Timestamps** use second precision: write `now()`, not `NOW(6)` (MySQL rounds a fraction into a `TIMESTAMP(0)` column).
4. **Re-queue** (transfer, deactivated agent): reset or delete the old offers before offering again (unique `(conversation_id, user_id)`), clear `assigned_agent_id`.
5. **One open live chat per session**: check `(visitor_session_id, status)` inside a transaction that locks the session row; the database does not enforce it.
6. **Ticket numbers** are assigned by the model; a unique violation on `ticket_no` is a retry, not an error.
7. **Visitor-facing responses** use `ConversationPublicData` / `MessageData::fromModel($m)` only. Staff responses may use `ConversationStaffData` and `forStaff: true`; neither ever exposes `token_hash`, `path`, `disk`, `sha256` or `original_name`.
8. **Lists** eager-load `category`, `assignedAgent`, `visitor`, `widget` (conversations) and `senderUser`, `attachments`, `conversation.visitor` (messages).
9. **Staff lists** start from `Conversation::visibleTo($user)`; single conversations are authorised with `ConversationPolicy::view()` (or `viewAsStaff()` in channel callbacks).

## Fix-round additions (after the P4 reviews)

- `visitors.external_id` is binary-collated (`utf8mb4_0900_bin` on MySQL, `utf8mb4_nopad_bin` on MariaDB) so host ids that differ by case/accent are different visitors; `visitor_sessions.network_hash` (HMAC of the client network bucket, never the IP) backs the queued-chats-per-network cap.
- `OfferData.ttlSeconds`; `SessionData` / `SessionLimitsData` / `RealtimeEndpointData` / `TransferTargetsData` Data classes.
- Settings: `chat.attachment_max_total_bytes` (30 MiB), `chat.attachment_url_ttl_minutes` (240); `chat.max_message_length` is capped at 16000. Signed attachment URLs are built from the configured app origin (never the request Host).
- Offline tickets without a category (a widget with none enabled) are visible to ALL active agents; the default category is the missed chat's topic, else the widget's first active one.
- Claim by the agent who already holds the chat is idempotent (`200`, no event). Animated GIFs are refused (a chat image is a still).
- Visitor-facing agent names never contain an e-mail address (`User::public_label`).
