## Interfaces between tracks

1. **Domain events (A dispatches, B consumes).** 4A dispatches the spine's `App\Domain\Chat\Events\*` after the state change commits (they are `ShouldDispatchAfterCommit`). 4B registers listeners (in `ChatServiceProvider`'s sibling `RealtimeServiceProvider` or an `EventServiceProvider`-style `Event::listen` block in its own provider, which the orchestrator registers) that build the broadcast payloads from the spine's `App\Data\Chat\Events\*Payload` classes. Event names and channels: [realtime-events.md](realtime-events.md). `message.created` goes out with `ShouldBroadcastNow` and the **visitor-safe** `MessageData` (staff-only fields reach staff through REST, never through the shared channel).
2. **`App\Domain\Chat\Realtime\ReverbEndpoint` (B provides, A consumes).** `public function forVisitors(): array{key: string, host: string, port: int, scheme: string}` (client-facing values from `config('broadcasting.connections.reverb')` / `config('reverb')`). 4A puts it in the `ws` block of `POST /public/sessions`. Until 4B is merged 4A creates a stub at exactly that path with that signature; the orchestrator keeps 4B's file on merge.
3. **Visitor broadcasting auth (B provides, D consumes).** `POST /api/v1/public/broadcasting/auth` (Bearer `vt_...` through the `visitor` middleware, form fields `socket_id`, `channel_name`): authorises only `private-conversation.{ulid}` of the conversation the session is bound to; anything else `403`. Pusher auth JSON on success. Staff use the standard `/broadcasting/auth` (session cookie or Sanctum bearer).
4. **Attachments (A provides).** `GET /api/v1/public/attachments/{attachment}` named `public.attachments.show`, middleware `signed`, `?thumb=1` for the thumbnail, serves from the private disk (short-lived redirect or streamed response). Staff reach attachments through the same signed URLs the `MessageData` carries.
5. **Presence (A provides, C consumes).** Minimal and real: `GET /api/v1/me/presence`, `PUT /api/v1/me/presence {status: online|away|offline}`, `POST /api/v1/me/presence/heartbeat`; `AgentPresence` rows; "online" for routing = status `online` or `away` with `last_heartbeat_at` within 90 s. Dispatches `PresenceChanged`. P5 replaces the storage with Redis, auto-away and the sweep behind the same service (`App\Domain\Presence\PresenceService`) and the same endpoints.
6. **Staff inbox data (C reads directly).** The Inertia controllers query the spine models (`Conversation::visibleTo($user)`, `ConversationStaffData::fromModel`) themselves; they do not call 4A's REST layer. Actions from the UI (claim, send, end, transfer, receipts, typing, presence) call the management API from `lib/chat-api/staff.ts` (cookie + `X-XSRF-TOKEN`), whose shapes are the REST contract; until 4A is merged C develops against MSW handlers built on `lib/chat/fixtures.ts`.
7. **Visitor API client (D).** Session creation is `POST /api/v1/public/widgets/{key}/sessions` (the widget key comes from the boot config); everything else carries only the bearer token. `lib/chat-api/visitor.ts` wraps the public endpoints with the bearer token; the token itself is stored by the loader in the host origin's `localStorage` and handed to the panel over the `init`/`session` postMessage as in [postmessage-protocol.md](postmessage-protocol.md) (the panel never stores it itself). Until 4A is merged D uses MSW.
8. **Echo clients.** Staff: `@laravel/echo-react` (`configureEcho` already in `resources/js/app.tsx`). Visitor (inside the iframe): `laravel-echo` + `pusher-js` with `authorizer`/`auth.headers.Authorization = Bearer vt_...` against the visitor auth endpoint; the websocket opens only on entering `queued` or when resuming a `queued`/`active` chat. Both use `lib/chat/events.ts` for event and channel names (`echoEvent()` adds the leading dot).

## Decisions (settled, do not re-open)

- **P4-D1 timestamps** are second precision; the claim SQL uses `now()` (not `NOW(6)`), the API prints `.000`.
- **P4-D2 offline tickets** are separate rows: `type=offline`, `status=queued`, no `queue_expires_at`; `missed` stays terminal; the visitor submits `POST /public/offline-tickets` (optional `missed_conversation` ulid). Lifecycle `queued -> active (claim by staff) -> closed` (`POST …/close`); staff reply through the normal message endpoint, which also e-mails the reply (queued mailable, `chat.offline_reply` view) because the visitor is gone. SMTP is configured by the admin later; in tests `Mail::fake()`.
- **P4-D3 one open live chat per visitor session**: not enforced by the database; the start action locks the session row (`lockForUpdate`) and checks inside a transaction (`409 conversation_exists`).
- **P4-D4 offers**: one row per (conversation, agent). A transfer or re-queue deletes/resets the old rows before offering again. Waves: wave 1 = agents with presence `online`; wave 2 (after `chat.offer_wave_delay_seconds`, delayed job) adds `away`; both only for agents who own the category and are under `max_concurrent_chats`. `queue_expires_at = queued_at + widget.queue_timeout_seconds`; a delayed `ExpireQueuedConversation` job plus a per-minute sweep (`chat:expire-queued`) mark it `missed`.
- **P4-D5 claim** is the guarded `UPDATE ... WHERE id=? AND status='queued' AND assigned_agent_id IS NULL`; capacity and category eligibility are checked first; the offer row becomes `accepted` for the winner and `taken` for the others (`ChatTaken`). `409 already_claimed {by}`.
- **P4-D6 messages**: `seq` allocated under a row lock on the conversation (`last_seq + 1`), `client_msg_id` idempotent (replay -> `200` with the original), unseen counters and `last_message_*` updated in the same transaction; `idle_expires_at` refreshed by messages only. A message to a conversation that is not `active` is `409 conversation_not_active`.
- **P4-D7 receipts**: `delivered_upto` / `seen_upto` (by seq) set `delivered_at` / `seen_at` on messages of the *other* side and reset the viewer's unseen counter; `MessagesSeen` is dispatched only when something changed.
- **P4-D8 end / rating**: either side ends an active live chat -> `ended`, `rating_requested = true`, `rating_window_expires_at = now + chat.rating_window_minutes`; the visitor rates (`1..5`, comment <= 2000) -> `closed` (`rated`); skipping or the window ending -> `closed` (`skipped` / `timeout`). Idle -> `closed` (`idle`), no rating prompt. A visitor cancelling a `queued` chat -> `closed` (`cancelled`).
- **P4-D9 attachments**: images only (`jpeg/png/webp/gif`), `chat.attachment_max_bytes`, `chat.attachment_max_dimension`; mime from `finfo` (never the client's), re-encoded with Intervention (strips EXIF), thumbnail 320 px, private disk, random path, signed URLs; an attachment belongs to one conversation and is referenced from one message.
- **P4-D10 rate limiters** (names): `public-session`, `public-message`, `public-upload`, `public-offline`, `staff-api` (per user), `broadcasting-auth`.
- **P4-D11 visitor-facing text is plain text.** Staff bodies are stored raw and rendered as text (React escapes); URL auto-linking is done at render time with `rel="noopener noreferrer nofollow"`.
- **P4-D12 session expiry**: a visitor session lives `chat.visitor_session_ttl_days`; an expired token gets `401 session_revoked` and the panel starts a fresh session (a new ticket).
- **P4-D13 agent visibility**: as implemented by `Conversation::visibleTo` (assigned, open offers while queued, queued offline tickets in a served category). `GET /conversations` for agents lists exactly that plus their closed chats.
- **P4-D14 mode 2** changes nothing here: `is_agent` / `is_admin` already come from the auth driver. A deactivated or role-revoked agent: 4B dispatches the spine's `StaffSessionRevoked` from every place a staff session is revoked or a role removed (`app/Auth/**`, `UpdateAgent`; it is the only track editing those files) and sends `session.revoked`; 4A listens for it (reasons `deactivated` / `role_removed`) and requeues that agent's active chats (`queued`, assignee cleared, new offers).
